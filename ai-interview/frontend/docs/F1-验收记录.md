### 测试覆盖点（F1-4/F1-5）

- `code=0` 解包 `data`、自动附带 `Authorization`；
- HTTP 200 + `code=10002` 抛 `BizError` 并保留 `traceId`；

## 5. 与计划的偏差与说明

| # | 偏差 | 原因/处理 |
|---|---|---|
| 1 | 依赖解析为 Vue 3.5.x、Element Plus 2.14.x、Axios 1.20.x（计划基线 Vue 3.4 / Element Plus 2.x / Axios 1.x） | `package.json` 仍用 `^` 范围；Axios 1.20 的响应泛型改为条件类型，`request<T>()` 在边界处显式收窄，运行行为不变 |
| 2 | F2~F5 业务页以 `PlaceholderView` 占位 | F1 只交付基座；占位页保证最终路由、三种布局、角色守卫可即时验证，F2 起逐页替换 |
| 3 | `src/components.d.ts` 入库 | unplugin-vue-components 生成；`build` 先跑 `vue-tsc`，入库后可保证全新克隆无需先启动 dev server 也能类型检查 |
| 4 | 占位首页 `/` 的重定向依赖 auth store | 首次打开时 user 可能尚未 restore；守卫在 restore 后再次按角色纠正（管理员回管理端、学生进学生端） |
| 5 | 原 `index.html` 已备份、`Dockerfile` 未改 | 按计划保留占位 Dockerfile 到 F6-4 与 P9 一起修复 |
| 6 | v1.1 新增液态玻璃视觉体系 | 按计划 §8.3.1 落地；纯 CSS、零新增依赖；F2~F5 页面复用 `GlassPanel`/`.glass-surface`，不另起主题 |
