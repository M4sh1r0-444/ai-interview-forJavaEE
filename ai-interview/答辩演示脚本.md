> 对应《系统实现方案》§19 的 15 步演示流程。**主路径为 Vue3 前端 UI**（F1~F6 已交付，19 页），每步附后端 API 兜底命令（终端演示/前端异常时使用）。
> 正式栈入口：`http://127.0.0.1`（80）；开发栈入口：`http://127.0.0.1:5173`。全程预计 **12~15 分钟**。

## 0. 演示前准备（答辩前 10 分钟完成）

```bash
cd ai-interview
# ① AI_PROVIDER=mock，零外网依赖；有真实 key 可现场切 qwen 对比

     -d '{"username":"demo01","password":"123456"}' | head -c 160          # code=0
```

- 演示账号：学生 `demo01 / 123456`（7 场历史、成长曲线有数据）；管理员 `admin / Admin@123456`。

## 1. 学生登录系统（UI）

【操作】打开 `http://127.0.0.1/login` → 输入 `demo01 / 123456` → 点击「登录」（或点演示账号卡片自动填入）。
【预期】跳转 `/home`，顶部显示「欢迎回来，演示学生」，无 403/白屏；刷新后仍保持登录。可先故意输错密码，展示「用户名或密码错误」（code 10002）；连续登录 6 次可展示 42901 限流倒计时（可选，慎用）。
【讲解】BCrypt 校验 + JWT 签发；Redis 黑名单支撑登出；路由守卫按角色分流（学生 `/home`、管理员 `/admin/dashboard`）；密码不落 localStorage，只持久化 token/expiresAt/user。

【API 兜底】`curl -s -X POST $BASE/api/auth/login ...` → `{code:0, data:{token, user:{role:"STUDENT"}}}`。

## 2. 选择 Java 后端岗位（UI）

【操作】左侧「岗位选择」→ `/positions` → 点击「Java 后端开发工程师」。
【预期】2 个种子岗位卡片（Java 后端 / Web 前端）；每卡展示默认轮次、技能数量、岗位说明；点击进入 `/positions/1`。
【讲解】岗位是组卷/评分/检索/推荐的隔离根；`GET /api/positions` 只返回启用岗位（清理后应只剩 2 个）。

【API 兜底】`curl -s $BASE/api/positions -H "$AUTH"`。

## 3. 查看岗位能力要求（UI）

【操作】岗位详情页查看「能力模型」技能表与「评分权重」卡片。
【预期】Java 岗 7 项技能，权重和 1.00（6×0.15 + 沟通 0.10）；评分公式：内容×0.5 + 表达×0.3 + 应变×0.1 + 匹配×0.1。
【讲解】技能权重可由管理端调整（第 14 步演示），报告总分/推荐优先级随之变化；权重和校验在前后端双重执行。

【API 兜底】`curl -s $BASE/api/positions/1/skills -H "$AUTH"`。

## 4. 选择文字或语音面试（UI）

【操作】点击「开始面试」→ `/interview/setup`；选择模式（文字/语音）、难度 1~5、轮次 5~8、时长 15~60 分钟；本次选**文字**、难度 2、5 轮、15 分钟。
【预期】默认值按岗位 `defaultRounds` clamp 到 5~8；越界不可提交；语音模式显示录音能力检测/不支持提示；CTA「创建并开始」防重复点击。
【讲解】设置参数进入后端校验（40002）；语音面试需 Chrome + 麦克风，离线时用文字/手工转写兜底。

【API 兜底】
```bash
SID=$(curl -s -X POST $BASE/api/interviews -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":1,"mode":"TEXT","difficulty":2,"rounds":5,"durationMinutes":15}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
curl -s -X POST $BASE/api/interviews/$SID/start -H "$AUTH" | head -c 300
```

## 5. AI 提出第一道问题（UI）

【操作】创建后自动进入 `/interview/{id}`，页面自动 start；观察首题气泡、顶部计时器、轮次进度、WS 状态徽标。
【预期】首题含背景铺垫；状态 `WAITING_USER`；计时从 15:00 递减；WS 显示「已连接」。
【讲解】主问题在 start 时一次性预写、组卷按题型比例 + 难度带 + 技能贪心覆盖；学生看不到未来轮次主问题（防偷题）。

【API 兜底】`POST /api/interviews/{id}/start` 返回首题 MessageVO。

## 6. 学生回答，系统保存内容（UI）

【操作】在输入框粘贴/输入一段结构化回答（如缓存击穿：互斥锁 + 逻辑过期），点击「提交回答」或 `Ctrl/Cmd+Enter`。
【预期】立即出现乐观 USER 气泡；按钮进入提交中禁用；1~2s 后 AI 追问/下一题出现；刷新页面消息不丢。
【讲解】文字回答是异步受理（`{accepted:true}` 只代表落库）；WS 通知 + REST 对账；关键词提取 + 知识库 FULLTEXT 检索 Top5 注入后续 Prompt。

【API 兜底】
```bash
curl -s -X POST $BASE/api/interviews/$SID/messages/text -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"roundNo":0,"content":"缓存击穿是热点 key 过期瞬间大量请求打库；用互斥锁保证单线程回源，或用逻辑过期异步重建，并加随机过期时间防止雪崩。"}'
```

## 7. AI 根据关键词进行追问（UI）

【操作】故意提交短而模糊的回答（如「就是加锁吧，别的我不太确定。」），观察 AI 追问气泡与「追问 N/3」计数。
【预期】同一轮最多 3 次追问，第 4 次强制换下一题；追问内容针对缺失得分点/模糊表达/失分点边界。
【讲解】7 条追问规则：缺失要点、模糊要求举例、失分点边界、覆盖充分升难度、连续低分降难度、连续高分深挖、同题追问≥3 换题；后端由逐题评分快照驱动。口径（D37）：升/降难度作用于**追问难度与提示强度**，主问题难度在组卷时锁定不漂移（FollowupRuleEngineTest R5/R6 用例断言 difficultyDelta ±1）。

【API 兜底】
```bash
node -e 'const ws=new WebSocket(`ws://127.0.0.1/ws/interviews/'$SID'?token='$TOKEN'`);ws.onmessage=e=>console.log(e.data)'
```

## 8. 完成 3~5 轮面试（UI）

【操作】继续作答至第 5 轮，或点击右上「结束面试」→ 二次确认 → 等待报告生成；也可演示「中止面试」终态。
【预期】finish 后输入区禁用、计时停止、WS 关闭/终态提示；自动跳转报告或显示「查看报告」；中止场次在历史中状态为 ABORTED。
【讲解】finish 异步受理（`{accepted:true,status:"FINISHED"}`）；报告由后台线程生成，WS `REPORT_READY` 通知；`finish` 幂等，兼报告重试入口。

【API 兜底】`curl -s -X POST $BASE/api/interviews/$SID/finish -H "$AUTH"`；轮次用尽/超时后端自动收卷。

### 8.1 语音作答（可选演示，UI）

【操作】新建一场 `AUDIO` 面试 → 房间内点「开始录音」→ 说话/或按提示允许麦克风 → 停止 → 查看转写 → 可编辑转写 → 提交。
【预期】录音计时、波形/状态、转写 final/interim；不支持/拒绝权限时提示并允许手工填写转写；提交后报告出现 `voice` 维度；报告/房间可受保护回放。
【讲解】MediaRecorder（webm/opus）+ Web Speech 转写后随 multipart 上送；后端做语速/停顿/语气词指标换算；音频走鉴权接口，不暴露静态 URL。离线或 ASR 不可用时，手工转写仍可提交（断网演练路径）。

## 9. 查看六维评估报告（UI）

【操作】`/interview/{id}/report`：查看总分环、TEXT 5 维雷达（AUDIO 6 维含 voice）、维度条、总结。
【预期】报告未就绪时显示「生成中」并自动轮询（10004 是正常态），1~3s 内恢复；失败时提供「重新生成」（finish 幂等）。
【讲解】逐题规则评分 → 难度加权聚合 → 岗位权重合成总分；报告可打印（`Ctrl/Cmd+P` 白底版式）。

【API 兜底】`sleep 2 && curl -s $BASE/api/interviews/$SID/report -H "$AUTH"`。

## 10. 查看回答证据、亮点和不足（UI）

【操作】报告页向下：逐题证据折叠（默认展开首题）、得分点覆盖/缺失、证据句、评分理由；亮点/不足/建议三列表；资源预览。
【预期】每项分数可追溯到题目/回答/得分点；空数组显示「无」的空态；资源预览失败不影响报告主体。
【讲解】评分不是黑盒：evidence/coveredPoints/missingPoints/reason 全部落库；报告失败可确定性重建。

## 11. 查看推荐练习和学习资源（UI）

【操作】报告页 CTA 或左侧「学习推荐」→ `/recommendations`。
【预期】Top3 短板技能、优先级、短板原因、资源/练习、错题重练、下一场建议；外链安全打开。
【讲解】优先级 =(100-掌握度)×岗位技能权重；四规则短板识别；报告落库事件预生成 Redis 缓存（TTL 10min）；无短板时输出通用提升计划。

【API 兜底】`curl -s "$BASE/api/users/me/recommendations?positionId=1" -H "$AUTH"`。

## 12. 查看能力成长曲线（UI）

【操作】左侧「能力成长」→ `/growth`；切换岗位查看不同技能曲线。
【预期】每技能一条曲线（时间轴升序 + current）；demo01 有历史数据；空态/错误态合理；图表随窗口 resize。
【讲解】掌握度随报告自动折算：首次直取，此后 旧×0.7 + 本次×0.3（难度加权），按会话幂等。

【API 兜底】`curl -s "$BASE/api/users/me/growth?positionId=1" -H "$AUTH"`；历史：`GET /api/users/me/history?page=1&size=10`。

## 13. 切换 Web 前端岗位，展示题目和评分标准差异（UI）

【操作】返回 `/positions` → 选择「Web 前端开发工程师」→ 查看 7 技能（html_css_js / browser_network / vue3 / engineering / performance / security / project_ux）→ 可新建一场前端面试看首题。
【预期】能力模型、题库、知识片段、学习资源全部按岗位隔离；报告权重随岗位能力模型变化。
【讲解】同一条流水线、两套岗位数据；positionId 是组卷/检索/评分/推荐隔离键。

## 14. 管理员进入后台修改题目或知识片段（UI）

【操作】

1. 退出学生账号 → `admin / Admin@123456` 登录 → 自动进入 `/admin/dashboard`。
2. 「题库管理」→ 筛选/分页 → 编辑一道题：修改题干/得分点 → 保存（version+1）；可演示 40003：另开 API/标签页用最新 version 先改，再在旧页面保存 → 冲突弹窗 → 「用我的内容覆盖」/「放弃」。
3. 「岗位与能力模型」→「评分权重」→ 调整 content/expression/total 三组权重，故意把组内和改坏 → 保存禁用并提示差值；恢复 1.00 → 保存回读。`/admin/evaluation` 会重定向到 `?tab=weights`。
4. 「知识库」→ 新增知识片段（标题/内容/关键词/技能多选）→ 成功回显 → 「重建索引」→ `rebuilt:true`；页面明确说明后端无列表/编辑/删除接口。
5. 「数据看板」→ 四卡（用户/场次/题量/均分）+ 近 7 日柱线（null 均分断点）→ 刷新。
6. 「学习资源」→ 新增/编辑/下架；「用户管理」→ 搜索/禁用/启用，当前 admin 行显示「当前」且开关禁用。

【预期】全部管理接口 ROLE_ADMIN；学生 token 访问任一 `/admin/*` → `/403`；题库逻辑删（DISABLED 行保留）；权重/资源/用户状态回读一致。
【讲解】18 个管理接口（方案 §10 原列 7 个，实际扩展）；乐观锁 version；审计日志；禁止自禁用。

【API 兜底（P10 已修正）】评分权重请求体是 `scoreWeights`，且三组必须组内完整、和=1：

```bash
curl -s -X PUT $BASE/api/admin/positions/1/weights -H "$ADMIN_AUTH" -H 'Content-Type: application/json' -d '{
  "scoreWeights": {
    "content":    {"technical":0.30,"depth":0.25,"logic":0.20,"evidence":0.15,"match":0.10},
    "expression": {"clarity":0.30,"fluency":0.20,"pace":0.20,"confidence":0.15,"completeness":0.15},
    "total":      {"content":0.50,"expression":0.30,"adaptability":0.10,"match":0.10}
  }
}'
# 改题：先取 id/version，再带 version 提交；旧 version → 40003
curl -s "$BASE/api/admin/questions?positionId=1&page=1&size=5" -H "$ADMIN_AUTH" | python3 -m json.tool | head -30
# 新增知识片段
curl -s -X POST $BASE/api/admin/knowledge -H "$ADMIN_AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":1,"title":"答辩演示片段","content":"答辩演示用知识片段：讲清一个完整考点即可，长度需大于 10 个字符，关键词与技能标签分别以逗号分隔字符串提交。","keywords":"答辩,演示,检索,知识片段","skillTags":"spring"}'
curl -s $BASE/api/admin/dashboard -H "$ADMIN_AUTH" | head -c 300
```

## 附：故障预案

| 现象 | 处置 |
|---|---|
| 正式栈起不来 | `docker compose ps` 看哪个服务挂；`docker compose logs backend --tail 50`（多为 .env 缺 JWT_SECRET/密码） |
| 80 端口显示 nginx 默认页 | P9 回归：确认 frontend 容器 `Exited (0)`、卷挂载 `/usr/share/nginx/html`、nginx 依赖 `service_completed_successfully`；重建 `docker compose up -d --build` |
| 页面 404/空白 | 检查 `curl http://127.0.0.1/` 内容与 assets 200；浏览器强刷；`docker compose logs nginx` |
| 登录 42901 限流 | 等待 60s；答辩现场避免连续快速登录；测试环境可 `APP_SECURITY_LOGIN_RATE_LIMIT_PER_MINUTE=1000` |
| 报告接口 code=10004 | 正常生成中，等 2~3s；报告页已自动轮询，也可点「重新生成」（finish 幂等） |
| WS 连不上/一直重连 | 检查 `/ws` 反代 Upgrade、Origin 白名单；房间会降级为轮询，仍可继续作答 |
| 麦克风/语音不可用 | 用 `127.0.0.1`/HTTPS + Chrome；改用文字或手工转写；答辩机提前授权麦克风 |
| 管理端权重保存失败 | 三组权重必须组内完整、和=1（±0.01）；看页面实时差值提示 |
| 想展示真实大模型 | `.env` 改 `AI_PROVIDER=qwen` + 填 `AI_API_URL/AI_API_KEY`，`docker compose up -d` 重建 backend；失败自动降级 mock |

> 演示结束收尾：`docker compose down`（卷保留）→ `docker compose -f docker-compose.dev.yml up -d` 恢复开发栈。
