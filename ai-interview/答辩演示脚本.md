# 答辩演示脚本 —— AI 模拟面试与能力提升平台（后端）

> 对应《系统实现方案》§19 的 15 步演示流程，逐条映射为**可直接执行的命令**（经正式栈 Nginx 入口 `http://127.0.0.1`，与浏览器同路径）。
> 前端为占位静态页（正式 Vue3 前端属前后端联调阶段），演示用 curl / IDEA `api.http` / Node WS 客户端驱动，功能链路完全一致。
> 全程预计 **12~15 分钟**；每步给出【操作】→【预期】→【讲解要点】。

---

## 0. 演示前准备（答辩前 10 分钟完成）

```bash
cd ai-interview
# ① 确认 .env 存在且 AI_PROVIDER=mock（离线可演示；有真实 key 可现场切 qwen 对比）
cat .env
# ② 停 dev 栈（正式栈共用 mysql-data 卷，两个 mysql 禁止同时跑）→ 起正式五服务栈
docker compose -f docker-compose.dev.yml stop
docker compose up -d          # mysql/redis/backend/frontend/nginx，镜像均已本地化
# ③ 探活
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/                 # 200 静态页
curl -s -X POST http://127.0.0.1/api/auth/login -H 'Content-Type: application/json' \
     -d '{"username":"demo01","password":"123456"}' | head -c 200          # code=0
```

- 演示账号：学生 `demo01 / 123456`（库内已有多场面试，历史/成长曲线有数据）；管理员 `admin / Admin@123456`。
- 打开浏览器 `http://127.0.0.1` 展示占位首页（平台定位 + 能力卡片）；接口演示用终端。
- 公共变量（每个终端先执行一次）：

```bash
BASE=http://127.0.0.1
TOKEN=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"demo01","password":"123456"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
AUTH="Authorization: Bearer $TOKEN"
ADMIN_TOKEN=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123456"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
ADMIN_AUTH="Authorization: Bearer $ADMIN_TOKEN"
```

---

## 1. 学生登录系统

【操作】上面公共变量里的登录命令（或 `api.http` 用例 2）。
【预期】返回 `{code:0, data:{token, user:{role:STUDENT,...}}}`。
【讲解】BCrypt 校验 + JWT 签发；Redis 黑名单支撑登出；登录限流 5 次/分/IP。可顺带演示错误密码 → code=10002。

## 2. 选择 Java 后端岗位

【操作】`curl -s $BASE/api/positions -H "$AUTH"`，随后 `curl -s $BASE/api/positions/1 -H "$AUTH"`。
【预期】2 个岗位；Java 后端岗位详情含能力模型。
【讲解】岗位是组卷与评分的根：技能权重直接参与报告总分与推荐优先级。

## 3. 查看岗位能力要求

【操作】`curl -s $BASE/api/positions/1/skills -H "$AUTH"`。
【预期】7 项技能（java_basics / concurrency_jvm / spring / mysql / redis_mq / project_design / communication），权重和=1（0.15×6 + 0.10）。
【讲解】权重可由管理端调整（第 14 步演示），报告总分 = 内容×0.5 + 表达×0.3 + 应变×0.1 + 匹配×0.1（岗位可调）。

## 4. 选择文字或语音面试

【操作】

```bash
SID=$(curl -s -X POST $BASE/api/interviews -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":1,"mode":"TEXT","difficulty":3,"rounds":5,"durationMinutes":15}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
curl -s $BASE/api/interviews/$SID -H "$AUTH"        # status=CREATED，参数已校验
```

【预期】会话创建成功，`status=CREATED`。
【讲解】`mode=TEXT/AUDIO` 两种作答通道；轮次 5~8、时长 15~60 分钟由配置约束；音视频走 multipart（第 8 步演示）。

## 5. AI 提出第一道问题

【操作】`curl -s -X POST $BASE/api/interviews/$SID/start -H "$AUTH"`。
【预期】返回首题（含背景铺垫的完整题干），同时 `interview_message` 预写全部主问题。
【讲解】组卷 = 题型比例（技术 50/项目 20/场景 20/行为 10）+ 难度带 + 技能贪心覆盖；主问题序列 start 时一次性落库防"答题中换题"。此时可另开终端挂上 WS（见第 7 步）收后续推送。

## 6. 学生回答，系统保存内容

【操作】

```bash
curl -s -X POST $BASE/api/interviews/$SID/messages/text -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"roundNo":0,"content":"缓存击穿指热点key过期瞬间大量请求直达数据库。对策首先是互斥锁保证只有一个线程回源，其次是逻辑过期：value 里带过期时间，异步刷新不阻塞请求；再者热点key可设置不过期加后台刷新。要注意与穿透（查不存在的key）和雪崩（大量key同时过期）区分：穿透用空值缓存和布隆过滤器，雪崩用过期时间加随机抖动。项目中我在商品详情页用过逻辑过期方案，QPS 峰值下数据库压力可控。"}'
sleep 2 && curl -s $BASE/api/interviews/$SID/messages -H "$AUTH" | python3 -m json.tool | tail -40
```

【预期】受理返回 `{accepted:true, roundNo:0}`；随后消息表出现 AI 追问。
【讲解】异步受理→后台链路：关键词提取（词典法）→ 知识片段 ngram FULLTEXT 检索 Top5 → 注入评分与出题 Prompt → 逐题评分快照 → 追问规则引擎。回答内容、转写关键词均落库留证。

## 7. AI 根据关键词进行追问

【操作】另开终端（第 5 步后即可挂）：

```bash
node -e 'const ws=new WebSocket(`ws://127.0.0.1/ws/interviews/'$SID'?token='$TOKEN'`);ws.onmessage=e=>console.log(e.data)'
# 回到主终端继续作答（可故意答短/模糊，触发 R1 缺点追问、R2 模糊追问）：
curl -s -X POST $BASE/api/interviews/$SID/messages/text -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"roundNo":0,"content":"就是加锁吧，别的我不太确定。"}'
```

【预期】WS 终端依次打印 `QUESTION / FOLLOW_UP / TIMER` 等事件；同一轮连续追问，第 4 次强制换下一题。
【讲解】方案 §6.5 七条追问规则全部落地：缺失得分点追问、模糊回答要求举例、失分点边界追问、覆盖充分升难度、连续低分降难度、连续高分深挖、同题追问≥3 强制换题——由逐题评分输入驱动。

## 8. 完成 3~5 轮面试（含语音作答演示）

【操作】重复第 6 步直到轮次用尽自动收卷，或 `curl -s -X POST $BASE/api/interviews/$SID/finish -H "$AUTH"`。
语音作答（另建 `mode=AUDIO` 会话）：

```bash
SID_AUDIO=$(curl -s -X POST $BASE/api/interviews -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":2,"mode":"AUDIO","difficulty":3,"rounds":5,"durationMinutes":15}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")
curl -s -X POST $BASE/api/interviews/$SID_AUDIO/start -H "$AUTH" > /dev/null
printf '\x1aE\xdf\xa3fake-webm-audio' > /tmp/answer.webm
curl -s -X POST $BASE/api/interviews/$SID_AUDIO/messages/audio -H "$AUTH" \
  -F "file=@/tmp/answer.webm;type=audio/webm" -F "roundNo=0" \
  -F "asrText=虚拟DOM是JS对象表示的树结构，diff 通过同层比较最小化真实DOM操作；key 帮助识别节点复用……" \
  -F "durationMs=150000"
# 受保护回放：curl -s -o /dev/null -w '%{http_code}\n' $BASE/api/interviews/$SID_AUDIO/messages/<mid>/audio -H "$AUTH"
```

【预期】finish 受理 `{accepted:true, reportId}`；音频回答消息含 `asrText/audioPath/audioDurationMs`；回放仅本人/管理员可访问。
【讲解】语音链路契约：前端 Web Speech 转写后随表单上送（后端不做 ASR）；语速/停顿/语气词换算 voice 维度；音频 UUID 落盘 `uploads/` 卷持久化。

## 9. 查看六维评估报告

【操作】`sleep 3 && curl -s $BASE/api/interviews/$SID/report -H "$AUTH" | python3 -m json.tool`。
【预期】`dimensionScores` 六维（AUDIO 场含 voice）均在 0~100；`totalScore` 已回写会话；逐题证据含得分点覆盖/缺失、证据句、评分理由。
【讲解】逐题规则评分（key_points 命中率等）→ 难度加权聚合 → 岗位权重合成总分；报告异步生成，失败可经 finish 幂等重试，重启后可确定性重建。

## 10. 查看回答证据、亮点和不足

【操作】同上输出的 `questionEvidence[]`（证据句/covered/missing）、`strengths`、`weaknesses`。
【讲解】每个分数都有证据句与理由可溯——回答理解不是黑盒；亮点/不足按维度聚合生成。

## 11. 查看推荐练习和学习资源

【操作】

```bash
curl -s "$BASE/api/users/me/recommendations?positionId=1" -H "$AUTH" | python3 -m json.tool
```

【预期】Top3 短板技能（优先级=(100-掌握度)×权重 降序）：`weaknessReasons`（四规则短板识别）、`resources/practices`（V6 学习资源库匹配）、`retryQuestions`（最近一场错题重练）、`nextInterviewSuggested`。
【讲解】报告落库事件驱动预生成推荐缓存（Redis TTL 10min）；无短板时输出通用提升计划，接口契约恒非空。

## 12. 查看能力成长曲线

【操作】

```bash
curl -s "$BASE/api/users/me/growth?positionId=1" -H "$AUTH" | python3 -m json.tool
curl -s "$BASE/api/users/me/history?page=1&size=10" -H "$AUTH" | python3 -c "import sys,json;d=json.load(sys.stdin)['data'];print('历史场次 total=',d['total'])"
```

【预期】每技能一条曲线（records 升序 + current）；demo01 已有多场，曲线多点。
【讲解】掌握度随每份报告自动折算：首次直取，此后 旧×0.7 + 本次×0.3（难度加权），按会话幂等。

## 14. 管理员进入后台修改题目或知识片段

【操作】

```bash
# 岗位评分权重调整（组内和=1 校验）
curl -s -X PUT $BASE/api/admin/positions/1/weights -H "$ADMIN_AUTH" -H 'Content-Type: application/json' \
  -d '{"weights":{"technical":0.45,"expression":0.25,"adaptability":0.1,"match":0.2}}'
# 改题（先列出取 id/version，再带 version 提交；重复用旧 version → code=40003 乐观锁冲突）
curl -s "$BASE/api/admin/questions?positionId=1&page=1&size=5" -H "$ADMIN_AUTH" | python3 -m json.tool | head -25
curl -s -X PUT $BASE/api/admin/questions/<id> -H "$ADMIN_AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":1,"type":"TECHNICAL","content":"<沿用或微调原题干，4~1000 字>","difficulty":4,"skillTags":["<沿用原标签>"],"version":<上一步返回的 version>}'
# 新增知识片段（即时进入检索词典）
curl -s -X POST $BASE/api/admin/knowledge -H "$ADMIN_AUTH" -H 'Content-Type: application/json' \
  -d '{"positionId":1,"title":"答辩演示片段","content":"答辩演示用知识片段：讲清一个完整考点即可，长度需大于 10 个字符，关键词与技能标签分别以逗号分隔字符串提交。","keywords":"答辩,演示,检索,知识片段","skillTags":"spring"}'
curl -s $BASE/api/admin/dashboard -H "$ADMIN_AUTH"       # 看板：用户/场次/题量/均分/近7日趋势
```

【预期】权重持久化回读一致；改题成功后 version+1，再用旧 version 重复提交 → 40003（并发保护）；新片段提交后立即能被下一场面试检索注入（skillTags 为逗号分隔字符串）；学生 token 访问以上任一接口 → 403。
【讲解】管理端 18 个接口全部 ROLE_ADMIN + 操作审计日志；题库逻辑删（DISABLED 不再组卷）；用户启停可禁登录。

## 15. 无网络环境下切换 MockAiProvider，完成离线演示

【操作】

```bash
bash qa/m6_offline_drill.sh
```

【预期】脚本自动完成：停 dev 栈 → 起隔离栈（mysql/redis/backend 零外网出口，容器内实测外网 IP/域名均不通）→ 断网证明 5 项全过 → **离线完整走通 面试（文字+语音、含追问）→ 六维报告 → 历史/成长/推荐 → 管理端 → WebSocket** → 恢复 dev 栈；结果留存 `qa/offline_drill_result.json`。
【讲解】`AI_PROVIDER=mock`（默认）为规则引擎实现：出题/追问/评分/报告全链路可解释、零外部依赖；真实大模型模式（qwen）含三级容错（重试→降级 mock→会话熔断），缺 Key 启动即显式失败。现场网络不稳时的兜底演示路径。

## 附：故障预案

| 现象 | 处置 |
|---|---|
| 正式栈起不来 | `docker compose ps` 看哪个服务挂；backend 重启看 `docker compose logs backend --tail 50`（多半是 .env 缺 JWT_SECRET/密码） |
| 登录 42901 限流 | 等待 60s 窗口重置即可（连续演示登录触发，非故障） |
| 报告接口 code=10004 | 报告仍在异步生成，等 2~3s 重试；finish 幂等可作重试入口 |
| 80 端口被占 | `docker compose down` 后改 docker-compose.yml 端口映射（如 8080:80），BASE 相应调整 |
| 演示中断网 | 正好顺势切第 15 步离线演示（本系统 mock 模式完全离线可用） |
| 想展示真实大模型 | `.env` 改 `AI_PROVIDER=qwen` + 填 `AI_API_URL/AI_API_KEY`，`docker compose up -d` 重建 backend；调用失败自动降级 mock 不中断面试 |

> 演示结束收尾：`docker compose down`（卷保留）→ `docker compose -f docker-compose.dev.yml up -d` 恢复开发栈。
